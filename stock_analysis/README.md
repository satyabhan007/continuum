# Stock Market Data Analyzer

A dependency-free Python toolkit for analyzing stock market data. It reads
daily OHLCV (Open/High/Low/Close/Volume) data from CSV files, computes
technical and risk metrics, and prints a human-readable report with optional
JSON/CSV exports. Python 3.9+ standard library only.

## Quick start

```bash
cd stock_analysis

# analyze one symbol (sample data is included)
python3 stock_analyzer.py AAPL.csv

# compare several symbols and export machine-readable results
python3 stock_analyzer.py AAPL.csv MSFT.csv NVDA.csv GME.csv KO.csv \
    --json report.json --csv metrics.csv --export-series series.csv

# analyze a custom date window with custom indicator parameters
python3 stock_analyzer.py AAPL.csv --start 2024-01-01 --end 2024-12-31 \
    --sma 10 30 100 --rsi-period 9 --risk-free 0.04

# regenerate the synthetic sample data (deterministic)
python3 sample_data.py                 # AAPL/MSFT/NVDA/GME/KO, 504 days
python3 sample_data.py --days 300 --seed 99 -o mydata

# run the offline test suite (no network required)
python3 test_stock_analyzer.py
```

## Files

| File | Purpose |
| --- | --- |
| `stock_analyzer.py` | The analyzer CLI: parsing, indicators, statistics, rendering, exports |
| `sample_data.py` | Deterministic synthetic OHLCV data generator (seeded random walk with regime shifts and seasonality) |
| `test_stock_analyzer.py` | Offline unit/integration tests (70 tests, live fetch tested via injected fakes) |
| `AAPL.csv`, `MSFT.csv`, `NVDA.csv`, `GME.csv`, `KO.csv` | Sample data generated by `sample_data.py` (504 trading days each) |

## Input format

Any CSV with a date column and a close price column works. Column names are
matched case-insensitively (`Date`/`date`/`Timestamp`, `Close`/`Close Last`/
`Price`, `Adj Close`, `Volume`, `Open`, `High`, `Low`). Missing OHLC columns
are filled from the close. Common date formats are accepted (`2024-03-15`,
`03/15/2024`, `Mar 15, 2024`, `20240315`, ...). Rows are sorted by date and
duplicates dropped (keeping the last). Files with BOM or UTF-16 encoding are
handled.

When an `Adj Close` column exists it is used as the price series by default;
pass `--raw-close` to prefer the raw `Close` column instead.

## Metrics computed

Per symbol:

- **Price action**: first/last/min/max close, 52-week high/low, distance from
  52-week high, current drawdown from peak.
- **Returns**: total return, CAGR (252 trading days/year), best/worst day,
  positive-day ratio, max up/down streaks, current streak.
- **Risk**: annualized volatility, Sharpe, Sortino, Calmar ratios, max
  drawdown (depth, peak/trough/recovery dates), historical 1-day VaR 95%,
  return skewness.
- **Indicators**: RSI (Wilder), SMA (20/50/200 default), Bollinger Bands with
  %B, MACD (12/26/9) with signal and histogram, ATR (14).
- **Signals**: trend classification (close vs SMA stack), golden/death
  crosses, MACD bullish/bearish crosses.
- **Volume**: total/average/latest volume, max-volume day, relative volume.

Multi-symbol: a comparison table sorted by total return and a Pearson
correlation matrix of daily returns (pairwise, common dates only).

## CLI options

```
files                  CSV file(s) to analyze
-f, --fetch SYMBOL     optional live fetch from Stooq (repeatable)
--start / --end        restrict analysis to a date range (YYYY-MM-DD)
--raw-close            use Close instead of Adj Close when both exist
--sma N [N ...]        SMA windows (default 20 50 200, needs >= 2)
--rsi-period N         RSI period (default 14)
--macd FAST SLOW SIGNAL  MACD parameters (default 12 26 9)
--bollinger WINDOW STD Bollinger settings (default 20 2)
--atr-period N         ATR period (default 14)
--risk-free RATE       annual risk-free rate as a fraction (default 0)
--top N                number of recent signal events to show (default 3)
--json PATH            write full results as JSON ('-' for stdout)
--csv PATH             write per-symbol metrics as flat CSV ('-' for stdout)
--export-series PATH   write per-day indicator series as CSV ('-' for stdout)
--no-report            suppress the stdout report
```

Exit codes: `0` success; `1` some inputs failed but others were analyzed;
`2` nothing could be analyzed.

## Live fetch note

`--fetch` uses Stooq's public daily-data endpoint, which requires no API
key. As of late 2026 Stooq serves a JavaScript browser-verification page to
non-interactive HTTP clients, so automated fetches usually fail with an
explicit error. The analyzer detects that block page and tells you to
download the CSV in a browser and pass the file path instead. All analysis
features work fully offline from local CSV files; the optional fetch path
needs the third-party `requests` package only.

A written-up analysis of the five bundled sample datasets (rankings, risk
profile, and cross-checks) lives in [`ANALYSIS.md`](ANALYSIS.md).

## Design notes

- **Stdlib first**: no numpy/pandas dependency; the analyzer uses `csv`,
  `statistics`, `math`, `dataclasses`, and `argparse`.
- **Percentages as fractions**: stored internally as fractions (0.12 = 12%),
  annualized with 252 trading days.
- **Deterministic sample data**: seeded PRNG (`random.Random(f"{symbol}-{seed}")`)
  makes every run reproducible; the committed CSVs are byte-identical to a
  fresh regeneration.
- **Tested offline**: the HTTP client is injectable, so live-fetch logic is
  unit-tested with fakes; the suite never touches the network.
- **Trend classification**: the close strictly above every defined SMA is
  "bullish", strictly below all is "bearish", straddling is "mixed", exactly
  equal to all is "neutral"; SMA-stack alignment is reported separately via
  golden/death crosses.
